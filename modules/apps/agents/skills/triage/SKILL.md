# Triage

GitHub remains the public intake and contributor conversation. Vikunja owns accepted internal execution. Hindsight owns durable private rationale and domain decisions. Never create a new internal planning issue on GitHub.

Every AI-authored public triage comment starts with:

```markdown
> *This was generated by AI during triage.*
```

## Public states

Use the repository's existing category/state labels when available:

- categories: `bug`, `enhancement`;
- states: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

Do not invent or install labels unless the maintainer asks. External PRs can use the same state vocabulary when the repo already treats them as intake.

## Review queue

Show oldest first:

1. unlabeled incoming public issues/eligible external PRs;
2. `needs-triage`;
3. `needs-info` with new reporter activity.

## Triage one item

1. Read the full public thread or PR diff and any linked Vikunja task.
2. Recall Hindsight for the project, feature and domain terms. Verify memories against current code.
3. Search the codebase for an existing implementation and prior rejection. Historical ADRs or old context files may be read as evidence, but do not update them.
4. Verify the claim: reproduce a bug or test the PR's stated behavior.
5. Recommend category/state and wait only when the maintainer's judgment changes the outcome.
6. If clarification is needed, ask specific questions in the public issue and use `needs-info`.
7. If accepted for internal execution:
   - create or update a task in the matching Vikunja project;
   - include the public issue/PR URL, outcome, requirements, acceptance criteria and verification steps;
   - apply `ready-for-agent` in Vikunja only when executable;
   - add one short public comment linking or stating that the work was accepted, without exposing private task details;
   - read the Vikunja task back and verify it.
8. If rejected, explain briefly and close/label the public issue as appropriate. Retain a durable rejection reason in Hindsight only when future agents should avoid re-proposing it.
9. Retain durable domain/decision context through `domain-modeling` with `project:<slug>` and `source:<agent>`. Never update `CONTEXT.md`, ADRs or `.out-of-scope` stores.

Public discussion stays on GitHub. Current internal status stays in Vikunja. Do not mirror routine status comments into Hindsight.
